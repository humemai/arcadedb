# The postgresql language: supported syntax (fork prototype)

Fork only (`humemai/arcadedb`, branch `feat/postgresql-prototype`). The table lists constructs added on top of the core of the language, so
a construct with no row here may still run. An unsupported construct is meant to be refused with an error (SQLSTATE `0A000` where the
language recognizes it), not answered differently. Known differences from PostgreSQL are named in the row notes and in the parity corpus
cases marked pending (such as `is-columns-public-rows`, identity columns in `information_schema`). The answers are compared with
PostgreSQL 18.7 by the parity corpus (`engine/src/test/resources/postgresql/corpus`).

Where the language behaves differently from PostgreSQL, and why, is on the [differences page](postgresql-differences.md).
What PostgreSQL's own regression files give, statement by statement, is on the [regression page](postgresql-regression.md).

| Construct | State | Notes |
|---|---|---|
| `CREATE [UNIQUE] INDEX [[IF NOT EXISTS] name] ON t [USING btree] (column [, ...])` | supported | The tree index of the engine. On `source_id`, `target_id`, or a record id only the name is recorded. The limits are on the [differences page](postgresql-differences.md#create-index). Fork issue #125. |
| `CREATE INDEX ON t USING hnsw (embedding vector_l2_ops \| vector_cosine_ops \| vector_ip_ops) [WITH (m = .., ef_construction = ..)]` | supported | An `LSM_VECTOR` index over a column declared `vector(n)`; the nearest-neighbour queries use it as they use one made with `sql`. |
| `DROP INDEX`, other methods and operator classes, expression and partial indexes, `INCLUDE`, `DESC`, `NULLS`, `CONCURRENTLY` | refused, `0A000` | |
| `CREATE TABLE [IF NOT EXISTS] t (column type [NULL \| NOT NULL] [DEFAULT constant] [UNIQUE] [PRIMARY KEY], ..., [CONSTRAINT name] UNIQUE (...) \| PRIMARY KEY (...))` | supported | Makes a vertex type; a unique index for each key. `SELECT *`, an `INSERT` without a column list, and the columns and keys in `information_schema` are those of PostgreSQL 18 (`PostgreSQLCreateTableTest`). The types and the limits are on the [differences page](postgresql-differences.md#create-table). Fork issue #118. |
| `source_id text NOT NULL REFERENCES t (rid) ON DELETE CASCADE` and the same for `target_id` | supported | The table is an edge type between the rows of the referenced tables; deleting a row deletes its edges. `t` is any table that `CREATE TABLE` made, unless it declares its own column `rid`, or a type of ArcadeDB `sql` with a property `id` (fork issue #151). Every other `REFERENCES` is refused, `0A000`. |
| `CREATE TABLE` in a transaction block; `TEMP`, `CHECK`, `serial`, identity and generated columns, `INHERITS`, `PARTITION BY`, `LIKE`, `CREATE TABLE ... AS`, type modifiers other than `vector(n)` | refused, `0A000` | The position of the refusal is in the error. |
| Values of a `jsonb`, array or `bytea` column: a literal (`'{a,b}'`, `'{"k": 1}'`, `'\x0aff'`), `ARRAY[...]`, a cast (`'{a}'::text[]`, `::jsonb`, `::bytea`), `$n` | supported | PostgreSQL's input rules and SQLSTATEs. A `$n` takes a text, or the Java value (`List` or array, `Map`, `byte[]`). On the wire `ParameterDescription` announces `jsonb`, `bytea`, the array type, and `real[]` for a `vector`, and a text of no declared type is read by the type of the column. The record holds it in the class of its property, so `sql` and openCypher read the same value. A `jsonb` object keeps the order of its keys as written (PostgreSQL sorts them); a decimal in it is stored as a double when a double holds the same number. |
| Values of a `vector` column (an `ARRAY_OF_FLOATS` property): `'[1,0,0]'`, `ARRAY[1,0,0]`, `::vector`, `$n` with a `float[]`, a list or a text | supported | pgvector's rules; wrong dimensions for the `LSM_VECTOR` index of the property are `22000`. The distances and a few written values are compared with a pgvector server (`PgVectorParityIT`); the rest follows pgvector's documented behaviour. |
| The distance operators `<->`, `<=>`, and `<#>`, and `ORDER BY embedding <=> $1 LIMIT k` | supported | With an `LSM_VECTOR` index of the metric of the operator (`EUCLIDEAN`, `COSINE`, `DOT_PRODUCT`), one ascending distance in `ORDER BY`, a `LIMIT`, and no `WHERE`, the index supplies the nearest rows, so the result is approximate; `EXPLAIN` names the search. Every other form is an exact scan. A CI test holds the mean recall at 10 of each operator at 0.90 or more at the default settings, on 10,000 random unit vectors of 64 dimensions (`VectorSearchRecallTest`). `DOT_PRODUCT` is meant for unit vectors. |
| Values of an `EMBEDDED OF T`, `LIST OF T`, or `MAP OF T` column, `T` a document type: an object, an array of objects, an object of objects | supported | Stored as embedded documents of `T`, which `sql` and openCypher read as such, and read back as written, without `@type` and `@cat` (`EmbeddedWriteTest`). An object that the type would change is refused, `0A000`; see the [differences page](postgresql-differences.md#embedded-documents). Fork issue #145. |
| Values of a `date[]` or `timestamp[]` column (`LIST OF DATE`, `LIST OF DATETIME` and its other precisions): `'{2026-01-05,2026-02-01}'`, `ARRAY[...]`, a cast, `$n` | supported | The input rules of `date` and `timestamp`, with their SQLSTATEs; the writes of `values-writes.tsv` are compared with PostgreSQL 18 (`PgParityIT`). The catalog and the wire report `_date` and `_timestamp`. `CREATE TABLE` declares the columns as `date[]` and `timestamp[]`, a `LIST OF DATE` and a `LIST OF DATETIME_MICROS`, compared with PostgreSQL 18 (`PostgreSQLCreateTableTest`). A list of links stays `text[]` and is not written. Fork issues #146 and #155. |
| `timestamptz` (`timestamp with time zone`): columns, keys, indexes, casts, literals, comparisons with `date` and `timestamp`, interval arithmetic, `extract`; `Z`, `UTC`, or an offset (`+02`, `+0200`, `+02:00`) after a time, in a text and in a parameter; a datetime with a zone as a parameter | supported | A `DATETIME_MICROS` property holds the instant as its time in UTC, which is what `sql` and openCypher read. It is shown as PostgreSQL shows it in the time zone `UTC` (`2026-03-01 10:00:00+00`). A `timestamp` ignores a zone after its text, as PostgreSQL does. In a session whose `TimeZone` is not UTC, a statement that reads or makes a `timestamptz` is refused (`0A000`): run `SET TIME ZONE 'UTC'`. Refused too: a zone name or abbreviation in a text, `AT TIME ZONE`, a `timestamptz[]` column, and a time before the year 1 or after 9999 in UTC. An offset of 16 hours or more is `22009`. Compared with PostgreSQL 18, pgjdbc, psycopg, and SQLAlchemy (`PostgreSQLTimestampTzTest`). Fork issue [#223](https://github.com/humemai/arcadedb/issues/223). |
| The clock: `now()`, `CURRENT_TIMESTAMP[(p)]`, `transaction_timestamp()`, `LOCALTIMESTAMP[(p)]`, `CURRENT_DATE`, also after `DEFAULT` (without a precision) on a `date`, `timestamp`, or `timestamptz` column | supported | One value for each transaction, read as it begins, as in PostgreSQL; a statement outside a transaction is its own. For a transaction that a caller of the engine API began, the first statement of the language in it reads the clock. In the schema the default is `sysdate()` of ArcadeDB `sql`, so a record that another language creates takes the time too (in UTC). `CURRENT_DATE`, `LOCALTIMESTAMP`, and a clock default on a `date` or `timestamp` column read the time in the session's time zone (fork issue [#237](https://github.com/humemai/arcadedb/issues/237)); `now()`, `CURRENT_TIMESTAMP`, `transaction_timestamp()`, and a default on a `timestamptz` column are refused (`0A000`) in a session whose time zone is not UTC. `CURRENT_TIME`, `LOCALTIME`, `statement_timestamp()`, and `clock_timestamp()` are refused. Compared with PostgreSQL 18, pgjdbc, psycopg, and SQLAlchemy (`PostgreSQLCurrentTimeTest`). Fork issues [#222](https://github.com/humemai/arcadedb/issues/222) and [#190](https://github.com/humemai/arcadedb/issues/190). |
| A value the record cannot hold as PostgreSQL does: a JSON array or scalar into a `MAP`, a key `@type` at the top of one, a null element in a typed list or a primitive array, an array of two or more dimensions, an `EMBEDDED` property without a declared document type, a collection of links | refused, `0A000` | Fork issue #138. `NULL` and `DEFAULT` work for these columns too. |
| `INSERT ... ON CONFLICT DO NOTHING`, with or without `(column, ...)` | supported | A row that breaks a unique index is skipped and not counted. With a target only the index on exactly those columns is an arbiter; a break of another index is `23505`. A target that no unique index matches is `42P10`. |
| `INSERT ... ON CONFLICT (column, ...) DO UPDATE SET ... [WHERE ...]` | supported | The row that is there is read by the table name or the alias, the proposed row as `EXCLUDED`; a bare column that both have is `42702`. A row that would change what the same statement wrote is `21000`. `DO UPDATE` without a target is `42601`. |
| `ON CONFLICT ON CONSTRAINT`, an expression or a predicate in the target, `ON CONFLICT` on an edge table | refused, `0A000` | Name the columns of the unique index instead. |
| `function(...) OVER ([PARTITION BY ...] [ORDER BY ...])` for `row_number`, `rank`, `dense_rank`, `lag`, `lead`, `first_value`, `last_value` and `count`, `sum`, `avg`, `min`, `max` | supported | The default frame of PostgreSQL: to the last peer of the row, the whole partition without `ORDER BY`. In the select list and in `ORDER BY` only: in `WHERE` or `GROUP BY` it is `42P20`. A name that is no window function is `42883`. |
| An explicit frame (`ROWS`, `RANGE`, `GROUPS`), a named window, `FILTER`, `DISTINCT`, `ntile`, `percent_rank`, `cume_dist`, `nth_value`, a window function in a query with `GROUP BY`, `HAVING` or an aggregate | refused, `0A000` | |
| `a CROSS JOIN b`, chains of them, and mixed with `INNER` and `LEFT` joins | supported | Every pair of rows: a nested loop that holds the right input in memory under the memory cap (`53200` over it), or a hash join when a `WHERE` term over both sides is an equality, as with `FROM a, b`. `CROSS JOIN ... ON` and `... USING` are `42601`. `NATURAL JOIN` stays refused, `0A000`. |
| The memory cap of an operator that keeps rows (hash join build, `GROUP BY`, derived table, `WITH`, set operation, subquery key set) | supported | One operator may keep a sixteenth of the maximum heap of the JVM in estimated row bytes, at least 64 MiB and at most 1 GiB (a JVM with 2 GiB: 128 MiB; with 4 GiB: 256 MiB). Over it the statement stops with `53200` and a hint, never an answer from part of the rows. The JVM property `arcadedb.postgresql.joinMemoryMb` (MiB) sets it. A `GROUP BY` counts each group it keeps (its key values and the state of its aggregates), not the input rows; what one group collects (the values of `count(DISTINCT x)`, the text of `string_agg`) is not counted. |
| The record id of a type (`rid`, or `id` in a type with no property `id`; a table that `CREATE TABLE` made lists it as `rid` where that name reads it, once a foreign key refers to the table) and the `id` of an edge, in `information_schema.columns` and `pg_attribute` | supported | Reported as `GENERATED ALWAYS AS IDENTITY`: `is_identity` `YES`, `identity_generation` `ALWAYS`, `column_default` NULL, `is_nullable` `NO`, `attidentity` `a` (the start, increment, maximum and minimum of an identity are NULL, the column is `text`). A client that reads the columns leaves them out of an `INSERT`, as it does against PostgreSQL. Unlike PostgreSQL, `atthasdef` is true and `pg_attrdef` holds the default `arcadedb_record_id()` (a label, not a function), which makes the SQLAlchemy ORM read a new key back with `RETURNING` (`PostgreSQLCatalogClientsTest`, fork issue #137). `psql` prints `generated always as identity`. |
| A value for such a column: `INSERT INTO t (rid, ...) VALUES ('#9:1', ...)`, `UPDATE t SET rid = ...` | refused, `428C9` | As PostgreSQL refuses a value for `GENERATED ALWAYS`: the engine gives the record id and a statement cannot choose it (a record cannot be created at a chosen position). `DEFAULT` is accepted and means the engine's value. `OVERRIDING SYSTEM VALUE` and `OVERRIDING USER VALUE` are refused, `0A000`. |
| Foreign keys in `information_schema`, `pg_constraint`, and `pg_get_constraintdef` (so also `\d` in `psql`, pgjdbc, and SQLAlchemy reflection) | supported | Listed for the declared ends of an edge type and for `LINK` properties. A key of an edge end has delete rule `CASCADE` (`confdeltype` `c`, `ON DELETE CASCADE`), because deleting a vertex deletes its edges. A key of a `LINK` column is not enforced (`enforced` `NO`, `conenforced` false, `NOT ENFORCED`): a write through this language refuses a link to a missing record (`23503`), but the referenced record can be deleted. |
| `gen_random_uuid()` | supported | A random (version 4) uuid, one per row. It is returned as text, because the language has no `uuid` type: it takes a `text` or `varchar` column and `gen_random_uuid()::text` is the same text. Not needed for an id: the record id is the engine's. |
| `a RIGHT [OUTER] JOIN b` and `a FULL [OUTER] JOIN b`, with `ON` or `USING` | supported | `RIGHT` keeps the rows of `b` that no row of `a` matches, `FULL` keeps both sides, with `NULL` on the missing side. A `WHERE` term stays above the join, as in PostgreSQL. With `USING` the merged column is `b`'s for `RIGHT` and `coalesce(a, b)` for `FULL`. A hash join (an equality in the condition) or, for `RIGHT` and for `FULL ... ON true`, a nested loop, each holding one input in memory under the memory cap (`53200` over it); never an index lookup or a walk. A `FULL JOIN` whose condition has no equality is `0A000`, as in PostgreSQL, and so is `FULL JOIN ... USING` on columns whose types cannot be hashed. `NATURAL` joins stay refused, `0A000`. |
| `a IS DISTINCT FROM b`, `a IS NOT DISTINCT FROM b` | supported | Two NULLs are the same, a NULL and a value are different, the answer is never NULL. Typed as `=` is: a mismatch of types is `42883`. |
| `power` of `double precision` with `NaN` or infinity | supported | The answers of PostgreSQL 18: `power(1, 'NaN')` and `power(-1, 'inf')` are `1`. Fork issue [#188](https://github.com/humemai/arcadedb/issues/188). |
| `OVER (... ROWS UNBOUNDED PRECEDING)` and `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` | supported | The frame ends at the current row, not at its last peer (aggregates and `last_value`). Any other frame, `n PRECEDING`, `FOLLOWING`, `RANGE`, `GROUPS`, `EXCLUDE`, stays `0A000`. |
| `VALUES (...), (...)` as a query: `FROM (VALUES (1, 'a'), (2, 'b')) AS t(a, b)`, `IN (VALUES ...)`, `WITH v AS (VALUES ...)`, `VALUES ... ORDER BY ... LIMIT`, a statement of its own | supported | A constant table. Its columns are typed as `UNION` types them (an unknown literal is `text` unless the other rows say otherwise, `1` and `2.5` make `numeric`, `1` and `'x'` is `22P02`) and named `column1`, `column2` when there is no alias list. Rows of different widths and `DEFAULT` are `42601`. More than 500 rows, `LATERAL (VALUES ...)` and `TABLE t` are refused, `0A000`. `INSERT ... VALUES` is the separate statement and still takes `DEFAULT`. |
| A subquery in a write: `IN`, `NOT IN`, a scalar subquery and `EXISTS` in the `WHERE`, `SET` and `VALUES` of `INSERT`, `UPDATE` and `DELETE` | supported | The subquery is planned as in a `SELECT` and sees the table as it was before the statement (it runs on the first row, the writes come after every match is found). `VALUES ((SELECT id FROM ...), ...)` gives the ends of an edge. |
| A correlated `EXISTS` or `NOT EXISTS` whose `WHERE` has terms that are not key equalities: a comparison, an `OR`, a term of the outer query alone, an expression over both sides inside a comparison or an arithmetic operator | supported | The equalities pick the candidate rows by hash, the other terms are tested on them with the three-valued logic of PostgreSQL; with no equality every row is a candidate. A scalar or `IN` subquery in a term counts with every column that it reads of either query (fork issue [#164](https://github.com/humemai/arcadedb/issues/164)). A term that mixes both sides inside a function, a `CASE`, or one such subquery, and a correlated `EXISTS` with `GROUP BY`, `HAVING`, `LIMIT` or an aggregate, stay `0A000`. |
| Number text in another notation, as a value of `int2`, `int4`, `int8`, or `numeric`: `'0x1F'`, `'0o17'`, `'0b101'`, and `_` between digits (`'1_000'`) | supported | Read as PostgreSQL 18 reads it: `22003` for a number that does not fit an integer type, `22P02` for a text that is no number. A `real` or `double precision` text in hexadecimal stays `22P02`, where PostgreSQL reads it (from reading the code, not tested). Fork issue [#201](https://github.com/humemai/arcadedb/issues/201). |
| `UPDATE t [AS a] SET ... FROM item [, ...] WHERE ...` | supported | Planned as a `SELECT` of the record id of the target and of each `SET` value, so the items are joins, derived tables (also with windows) and subqueries as in a query. A target row that no joined row reaches is not changed; one that several reach is changed once, by the first. `RETURNING`, an edge table as the target and a table without a record id column are `0A000`; `DELETE ... USING` stays `0A000`. |
| `a ILIKE b [ESCAPE c]`, `a NOT ILIKE b [ESCAPE c]` | supported | The pattern and `ESCAPE` rules of `LIKE` (`%`, `_`, backslash by default, empty `ESCAPE` turns escaping off, `22025` and `22019`), with both sides folded to lower case the way the engine's `lower()` does (Unicode simple case mapping; a PostgreSQL server with the `C` collation folds ASCII letters only, so a non-ASCII letter can differ there). `NULL` on either side gives `NULL`. A number is `42883`, as in PostgreSQL. `SIMILAR TO` stays refused, `0A000`. |
| The name of an output column that has no alias | supported | As PostgreSQL 18 names it. A cast or a `CASE` keeps the name of a column, a function, or a subquery below it (`CASE` looks at its `ELSE`), and otherwise it is the type of the outer cast, or `case`; `EXISTS` is `exists`. Fork issues [#185](https://github.com/humemai/arcadedb/issues/185) and [#186](https://github.com/humemai/arcadedb/issues/186). |
| `string_agg(expr, delimiter)`, `string_agg(DISTINCT expr, delimiter)` | supported | `text`. An unknown-typed literal resolves to text, a number is `42883`. A `NULL` value is skipped and brings no delimiter, a `NULL` delimiter joins without one, no value gives `NULL`. Without `DISTINCT` the pieces come in input order; with `DISTINCT` PostgreSQL sorts them, and so does the engine. `string_agg(... ORDER BY ...)`, `string_agg(...) OVER (...)`, `FILTER` and `bytea` are refused, `0A000`. |
| `array_agg`, `json_agg`, `jsonb_agg`, `json_object_agg`, `bool_and`, `bool_or`, `every`, `bit_and`, `bit_or`, `stddev`, `variance`, `mode`, `percentile_cont` and the like | refused, `0A000` | They exist in PostgreSQL, so the answer is "not supported", not `42883`. |
| A number out of range for `real`, `double precision`, or `numeric` | supported | `22003`, as in PostgreSQL 18: a text or a number that a floating point type turns into infinity or zero, though it is neither, and a `round` that gives more digits than `numeric` holds. Fork issue [#197](https://github.com/humemai/arcadedb/issues/197). |
| A correlated scalar subquery or `IN (SELECT ...)` subquery (it reads a column of the query around it): `(SELECT count(*) FROM t WHERE t.k = o.k)` in the select list, `WHERE`, `ORDER BY`, `SET` and `VALUES`, with any comparison, aggregate, `ORDER BY ... LIMIT` or join inside | supported | Run as PostgreSQL runs it: once for each row of the outer query, with the outer columns it reads fixed to that row's values, so a key equality on an indexed column is an index lookup; an outer row with the same values as an earlier one gets the earlier answer (the last 10000 distinct value sets are kept). The innermost scope wins for an unqualified name. More than one row is `21000`, no row is `NULL`. A relation or column that nobody has is still `42P01` or `42703`. Known limit: an aggregate inside the subquery whose arguments read only outer columns belongs to the outer query in PostgreSQL; here it is refused, `0A000` in the select list, `HAVING` and `ORDER BY`, `42803` in `WHERE`. |
| `INSERT ... SELECT` with a `NULL` or a string literal in the select list: `INSERT INTO t (a, b) SELECT x, NULL FROM s` | supported | An output that is only `NULL` or a string literal keeps the type `unknown` and the target column decides it, as PostgreSQL resolves it: `NULL` is `NULL` of the column's type, `'42'` is a number for a number column (`22P02` when it is not one). Any other expression keeps its type, so a `text` expression into a number column is `42804` and needs a cast. Before, every literal was `text` first and `NULL` into a `bigint` column was `42804`. |
| `sqrt` of a `numeric` | supported | A `numeric` with the digits of PostgreSQL 18, and `2201F` for a negative number; the root of any other number is `double precision`. Fork issue [#187](https://github.com/humemai/arcadedb/issues/187). |
| A type modifier in a cast: `numeric(p,s)`, `varchar(n)`, `timestamp(p)` (also on `localtimestamp(p)`), `vector(n)` | supported | Applied as PostgreSQL applies it: a `numeric` is rounded to the scale (`22003` if it does not fit), a `varchar` is cut to the length, a timestamp is rounded to the precision (a half goes away from 2000-01-01), a precision above 6 is 6 (without PostgreSQL's warning). A modifier out of range is `22023`, and a modifier on a type that takes none (`text(3)`, `int4(3)`, `date(3)`) is `42601`, as in PostgreSQL. A type the language does not have (`character(n)`, `timestamptz`, `time`) and a precision on `interval` are `0A000`. |
| A subquery in a condition of a join, in `WHERE` or `ON`: `FROM a, b WHERE a.x IN (SELECT d.y FROM d WHERE d.k = b.g)` | supported | The condition is evaluated where the columns it reads are, the ones inside its subquery included, so a column of the join wins over one of a query around it. Compared with PostgreSQL 18 (`PostgreSQLJoinSubqueryTest`, fork issue [#170](https://github.com/humemai/arcadedb/issues/170)). The limits of a correlated `EXISTS` and of a correlated subquery above still apply. |
