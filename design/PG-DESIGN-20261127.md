## 1. Principle

> Write ordinary PostgreSQL and get PostgreSQL 18's answer, or an error that says what to write instead. ArcadeDB stores records, so full compatibility is not the aim, and nothing outside a short listed set may answer differently without an error. Agents are the main users and learn the database from `information_schema` and from error text, so both must be true and must name the next step. Humans check the results, so rows, types, and ids should look like PostgreSQL's wherever they can. Where PostgreSQL's meaning needs engine work, refuse instead of approximating.

### How to measure it

Corpus: what an agent writes when told only "PostgreSQL 18", given a task and the database's own `information_schema`, with no dialect notes. It must include schema creation. Every statement runs on PostgreSQL 18 and on the language over the same data. The audit corpus (`memory`, `web`) is the start; model-written scripts come on top.

| number | definition | proposed target |
| --- | --- | --- |
| M1, runs as written | non-volatile statements that match PostgreSQL 18 (same columns, rows, and count, or same SQLSTATE) with no replacement or repair | both schema scripts run to the end; set a percentage after work items 1 to 4 |
| M2, error guides | of the failing statements: share whose error names a next step (static), and share a model fixes on its next attempt from the error alone | static 100%, repair at least 90% |
| M3, silent differences | statements that succeed where PostgreSQL answers otherwise or refuses, outside the listed set | 0 |

Report M1 per class (schema, write, read, transaction, discovery), because one refused `CREATE TABLE` hides everything after it.

Today, from the audit run:

| corpus | non-volatile statements | match as written | match with hand replacements | refused (replacement run) | of those, with `Hint:` or a pointer to `sql` |
| --- | ---: | ---: | ---: | ---: | ---: |
| `memory` | 80 | 0 | 23 | 54 | 5 |
| `web` | 168 | 24 | 89 | 58 | 15 |
| `features` (probes, not a frequency sample) | 121 | not run | 27 | 85 | 4 |

As written, 45 of the 79 refusals in `memory` and 55 of the 99 in `web` are `42P01`, a table that was never created. Some errors say what to do without the word `Hint` ("delete the edge and insert it again"), so the last column is a lower bound.

The earlier fit test (#35, phase 4: reads and writes over a schema already made, no DDL, my own questions) looked much better with the schema text alone: reads correct on the first try 96.9 to 97.4%, writes 78.0 to 86.0% on the first try and 95.5 to 100.0% within 3 attempts. So retries on error text work, and the unmeasured gap was schema creation and ordinary application constructs.

## 2. How other systems define it

| system | what the page says | how I read it |
| --- | --- | --- |
| SQLite | "not intended as a replacement or competitor" to other engines; foreign keys off by default ([quirks](https://www.sqlite.org/quirks.html)). `rowid` is shadowed by a user column of that name and may change on `VACUUM` unless it is an `INTEGER PRIMARY KEY` ([rowid](https://www.sqlite.org/rowidtable.html)). A foreign key cannot refer to the rowid ([foreign keys](https://sqlite.org/foreignkeys.html)) | fetched |
| DuckDB | "closely follows the conventions of the PostgreSQL dialect. The few exceptions to this are listed on this page" ([compatibility](https://duckdb.org/docs/2.0/sql/dialect/postgresql_compatibility.html)). `rowid` is shadowed by a user column, and using it as an identifier is strongly advised against ([SELECT](https://duckdb.org/docs/2.0/sql/statements/select.html)). Foreign keys are checked ([constraints](https://duckdb.org/docs/2.0/sql/constraints.html)) | fetched |
| CockroachDB | "supports the PostgreSQL wire protocol and the majority of PostgreSQL syntax", with a list of gaps ([compatibility](https://docs.cockroachlabs.com/docs/stable/postgresql-compatibility)); a hidden `rowid` when there is no primary key ([primary key](https://docs.cockroachlabs.com/docs/stable/primary-key)); `SERIAL` is "provided only for compatibility" and its values are not sequential ([serial](https://docs.cockroachlabs.com/docs/stable/serial)) | fetched |
| CockroachDB errors | unimplemented features answer `0A000` with a hint and an issue link ([v20.1 limitations](https://www.cockroachlabs.com/docs/v20.1/known-limitations)) | search summary |
| YugabyteDB | unsupported features listed with tracking issues; "not supported yet" with `0A000` ([compatibility](https://docs.yugabyte.com/latest/explore/ysql-language-features/postgresql-compatibility/)) | search summary; the page did not load |
| Aurora DSQL | "designed to be PostgreSQL compatible"; UTC; optimistic concurrency answers serialization errors and applications retry; foreign keys supported ([migration guide](https://docs.aws.amazon.com/aurora-dsql/latest/userguide/working-with-postgresql-compatibility-unsupported-features.html)) | fetched |
| BigQuery | keys are declared `NOT ENFORCED` and not checked ([keys](https://docs.cloud.google.com/bigquery/docs/primary-foreign-keys)) | search summary |
| PostgreSQL 18 | `NOT ENFORCED` foreign keys and checks: "the database system will not check the constraint" ([CREATE TABLE](https://www.postgresql.org/docs/18/sql-createtable.html)); a hint is for "suggestions about what to do to fix the problem" ([style guide](https://www.postgresql.org/docs/current/error-style-guide.html)) | fetched |
| PostgreSQL SQL/PGQ | reverted: no property graph source file on `master` or `REL_19_STABLE` today, revert commit [`b1f106c80c`](https://github.com/postgres/postgres/commit/b1f106c80c) of 2026-09-07 | GitHub API |
| ordinary DDL | SQLAlchemy emits `SERIAL` for integer keys ([dialect](https://docs.sqlalchemy.org/en/20/dialects/postgresql.html)); Django 4.1 and later emit identity columns ([notes](https://docs.djangoproject.com/en/5.2/releases/4.1/)); Supabase's AI style guide asks for `id bigint generated always as identity primary key` and shows `author_id bigint references authors (id)` ([guide](https://supabase.com/docs/guides/ai-tools/ai-prompts/code-format-sql)) | fetched |
| Prisma | required relations default to `ON DELETE RESTRICT ON UPDATE CASCADE` ([referential actions](https://www.prisma.io/docs/orm/prisma-schema/data-model/relations/referential-actions)) | search summary |

Inferred: state a goal plus a list of differences, never plain "compatible"; keep the hidden row id under its own name; expect integer auto keys; say plainly when a constraint is not checked; leave graph syntax to openCypher.

## 3. The choices

| # | choice | verdict | effort |
| --- | --- | --- | --- |
| 1 | `id` and `rid` | change: `rid` everywhere, no `id` alias on `CREATE TABLE` tables | S |
| 2 | record id is `text` | keep | none |
| 3, #213 | ends hold record ids | change: finish #213 with two additions | M to L, in progress |
| 4 | edge ends declared on the edge type | keep | none |
| 5 | updating an end refused | keep; allow `UPDATE ... FROM` on other columns of a link table | S to M |
| 6 | case folding, then a unique case-insensitive match | keep | none |
| 7 | only declared properties are columns | better hint now, hidden column later | S, then M |
| 8 | maps `jsonb`, lists arrays | keep the types, add the operators | M |
| 9 | `jsonb` key order and decimals | keep storage; fix equality and output text | S |
| 10 | record id reported as identity | keep | none |
| 11 | separate language | keep | none |

### Choice 1: the record id's name

```sql
CREATE TABLE doc (title text);
SELECT title FROM doc WHERE id = '1';
-- PostgreSQL 18: 42703
-- today: succeeds with no rows; UPDATE and DELETE are accepted too (G92 to G95)
-- proposed: 42703. HINT: doc has no column id; read rid, or declare id bigserial PRIMARY KEY.
```

On such a table `ORDER BY id DESC LIMIT 3` returned `t20, t18, t16` where a PostgreSQL identity column gives `t30, t29, t28` (D20): the "id" is record id text, so "latest rows" is wrong with no error. Proposal: every table reads `rid` (hidden where `id` already is the record id; today `rid` is `42703` on an `sql` or openCypher type without its own `id`); a `CREATE TABLE` table stops answering `id`. Types made with `sql` keep `id`, so #38 stands. This reverses one point of #118 and removes special binding rules.

### Choice 2: record id as `text`

Keep. A number would change the catalog, the wire, and the values exchanged with `sql` and openCypher, and once `serial` works an agent's tables have their own integer keys. The cost is in the hints: `p.id = k.source_id` answers `42883` with "You might need to add explicit type casts" (D08, D13). A cast to `bigint` fails with `22P02` (2 calls in #35 phase 5). Inferred, not run: `k.source_id = p.id::text` would return no rows with no error. Fix the hint.

### Choice 3 and #213: join a link table on the table's own key

```sql
SELECT q.name FROM person p JOIN knows k ON k.source_id = p.id JOIN person q ON q.id = k.target_id;
-- today: 42883 text = bigint (D08), and INSERT INTO knows (source_id, target_id, since) VALUES (1, 2, 2022) is 23503 (D04)
-- #213: both work; the engine still stores a link between two records
```

Keep the design on #213. Add `ON DELETE RESTRICT` (behaves as `NO ACTION` here, nothing is deferrable) and `ON UPDATE CASCADE` (a link already shows a changed key, because the end is read from the record, so only the declaration is new). Keep the column names `source_id` and `target_id`; the refusal should show them.

Verdicts on its open choices:

| | open choice | verdict | why, and the condition |
| --- | --- | --- | --- |
| a | reading an end that `sql` or openCypher pointed at the wrong table or a keyless record is `23503`, never `NULL` | keep | `NULL` would drop rows from joins with no error and break the declared `NOT NULL`. One bad link fails every scan that reads that end, so the error must give the edge id and a repair that works without reading the end, and a test must run that repair |
| b | default `NO ACTION` holds only for writes of this language; `sql` and openCypher still cascade | keep | ordinary DDL means `NO ACTION`, and cascading instead would lose rows silently; edge end checks already work this way. Say it on the differences page. Test a delete racing a link insert (I expect `40001`, inferred, not tested) |
| c | `int` referencing a `bigint` key is `0A000` although PostgreSQL accepts it | keep | the end shows the key's type, so accepting would misreport the declared column. One retry if the hint is the exact column text. Count it in M1 and revisit if it recurs |
| d | a declared column that stops being unique makes the whole link table `55000` | keep | PostgreSQL would refuse the drop; here `sql` can drop it, and falling back to record ids would change types silently. The error gives the exact `sql` repair. A future `DROP INDEX` in the language must refuse with `2BP01` |

PR #219 must not merge alone. From its diff, `information_schema` reports `NO ACTION` for an end declared with `source_on_delete = 'NO ACTION'`, while delete rules are not in the PR, so a delete still cascades. Merge it together with the writes half (branch `feat/pg-link-keys-writes`, failing tests only so far).

### Choices 4 to 11

- **4, keep.** `CREATE TABLE` writes the declaration, so an agent never types it. The engine feature is an upstream question already asked.
- **5, keep.** "delete the edge and insert it again" (12 calls in #35 phase 5) is the model for other errors. Change: `UPDATE ... FROM` with a link table as target is refused entirely (first attempts in phase 4: Haiku 4, Sonnet 12, Opus 3); allow it for columns other than the ends.
- **6, keep.** It finds openCypher's CamelCase types without quotes; two candidates are an error. DuckDB also matches names case-insensitively.
- **7, change in two steps.** Now: the `42703` hint gives the exact statement, `{sql}CREATE PROPERTY City.name STRING`. Later: a hidden `jsonb` column `properties`, not in `*`, so `SELECT properties ->> 'name' FROM "City"` works (D33 to D35). An unknown name must stay `42703`.
- **8, keep the types.** The gap is operators: `->>`, `->`, `@>`, `= ANY`, `array_agg`, `jsonb_agg`, `jsonb_build_object`.
- **9, keep storage.** `WHERE meta = '{"a": 1}'` is `0A000` (H32) and `DISTINCT` keeps equal values apart (#189): compare by value. Print as PostgreSQL does: `{"a": 1}`, not `{"a":1}` (H33), and `1024`, not `1024.0`, for floats (F66).
- **10, keep.** SQLAlchemy writes work with it (#137).
- **11, keep.** `sql` gave different cells for 21 of 86 shared single-table statements (#1) and scored lower than `postgresql` for models in #35 phase 4.

| --- | --- | --- | --- | --- |
| R1 | a refused `BEGIN ...` leaves the session in autocommit | change: abort the block; support `READ ONLY` | S, S | H02 to H05, G68 to G71 |
| R2 | `CREATE TABLE` in a transaction block `0A000` | change | M | psycopg defaults and SQLAlchemy `create_all` fail |
| R3 | `serial`, `bigserial`, identity `0A000` | add | M | P01 to P04; with plain `bigint` keys instead, 8 (`memory`) and 6 (`web`) later statements fail with `23502` |
| R4 | `timestamptz`, ISO text with `T` and `Z`, `now()`, defaults that are not constants | add, UTC instants | M | P06, P07, F50, F111, F112 |
| R5 | `uuid`, `varchar(n)`, `numeric(p,s)`, `DEFAULT '{}'` | add | M | P05, P08, P09, P11, P12, P28 |
| R6 | `REFERENCES` on an ordinary column `0A000` | accept when written `NOT ENFORCED`; otherwise refuse and say so | S | P18, P19 |
| R7 | `ALTER`, `DROP`, `CREATE EXTENSION` `0A000` | add `ADD COLUMN`, `DROP TABLE [IF EXISTS]`, and `CREATE EXTENSION IF NOT EXISTS vector` as a no-op | M | `ALTER` 8 times in `web`; `CREATE EXTENSION` is the first `memory` statement |
| R8 | `= ANY`, JSON operators and aggregates, `ORDER BY` in an aggregate, `LATERAL`, `FILTER`, string functions | add in order of count | M per group | refusal lists of the three corpora |
| R9 | `FOR UPDATE` `0A000` | keep; hint that no row is locked and `40001` must be retried | S | 200 increments per session: 153 and 135 succeeded, 47 and 65 got `40001`; PostgreSQL 200 and 200 |
| R10 | `SAVEPOINT` accepted, `ROLLBACK TO` refused | keep; the message must say the whole transaction is now aborted | S | D66 to D69; SQLAlchemy `begin_nested()` loses the outer rows |
| R11 | `WITH RECURSIVE` | keep refused; hint with a one-line openCypher form | S | `memory` |
| R12 | `MERGE`, views, types, schemas, sequences, `CHECK`, temporary tables, `DO` | keep refused for now; each hint names a replacement or says there is none | S | probes and `web` |
| R13 | `version()` says PostgreSQL 12.0 | report 18, after the client tests pass | S | G11; risk: clients may then send newer catalog queries |

R1, the one that changes data:

```sql
BEGIN ISOLATION LEVEL SERIALIZABLE;      -- 0A000
UPDATE acc SET amount = 0 WHERE id = 1;  -- today: runs and commits at once
ROLLBACK;
SELECT amount FROM acc WHERE id = 1;     -- 0 here, 100 on PostgreSQL 18 (H05)
-- proposed: the failed BEGIN aborts the block, so the UPDATE is 25P02
```

R2: run the statement at once and, if the block rolls back, drop the new table if it is still empty. Other sessions see it before commit; list that. `ALTER` and `DROP` stay refused in a block.

R3: values start at 1 and increase, because agents hard-code ids 1 and 2 in seed rows; gaps are allowed. I found no sequence in the engine's `sql` grammar, so this needs a counter committed in its own short transaction (inferred, not designed). CockroachDB's non-sequential values are the precedent I would not follow.

R4 also closes a silent difference: `SET TIME ZONE 'Asia/Seoul'` is accepted and `LOCALTIMESTAMP` stays UTC (H10, H11). Convert, or refuse such expressions while the zone is not UTC.

R6:

```sql
CREATE TABLE book (id bigint PRIMARY KEY, author_id bigint REFERENCES author (id));
-- today: 0A000
-- proposed: 0A000. HINT: foreign keys outside link tables are not checked here; write NOT ENFORCED after the reference.
CREATE TABLE book (id bigint PRIMARY KEY, author_id bigint REFERENCES author (id) NOT ENFORCED);
-- proposed: accepted, listed as enforced = NO; PostgreSQL 18 does the same with this text
```

Enforcing it instead is not simple (inferred): under optimistic concurrency a parent delete and a child insert can both commit unless the insert also touches the parent.

R7: today the hint sends the agent to `sql`, but `{sql} ALTER TABLE acc ADD COLUMN extra text` is a `42601` (H22), because `sql` is not PostgreSQL.

### Errors

The wire sends message, severity, code, and position only (`PostgresNetworkExecutor.writeError`); hints are glued into the message. Send them in the protocol's hint field, give every refusal one, and fix these first:

```text
today     42883 operator does not exist: text = bigint. Hint: ... You might need to add explicit type casts.
proposed  same code. HINT: knows.source_id holds record ids; join on person.rid. A cast will not match them.

today     42703 column "name" does not exist. Hint: ... declare the property with CREATE PROPERTY in the sql language
proposed  same code. HINT: run {sql}CREATE PROPERTY City.name STRING, then repeat the statement.

today     0A000 The operator ->> is not supported by the postgresql language
proposed  same code. HINT: select the jsonb column whole and read the key in your program.
```

Add a one-screen "what to write here" block at the top of the differences page. In #35 phase 4 a short reference block raised Haiku's first-try writes from 78.0 to 93.8%, and a second variant lowered Sonnet's first-try reads by 7.2 points through replies with prose, so keep it short.

## Limits

- The audit corpus was written by an agent for an audit, so it is a fit sample, not a held-out one. "Match with hand replacements" includes knock-on effects of the replacements.
- No proposal above has been built or run. Effort sizes are judgments. What PostgreSQL does when a referenced unique index is dropped (verdict d) is from my knowledge, not from a run.
